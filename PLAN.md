## 1. The assignment in my own words

Build an online shop that runs entirely in the browser using **HTML, CSS, JavaScript and jQuery**.
The page never talks to a database directly. Instead it sends **JSON over AJAX** (`$.ajax`) to
**Firebase REST APIs**:

```
 Browser (HTML/CSS/JS/jQuery)  --- JSON over AJAX --->  Firebase
                                                          - Auth (identitytoolkit / securetoken)
                                                          - Firestore NoSQL data (REST v1)
```

There are two kinds of users:

- **Admin**: one person, identified by a single email address. The admin manages the product
  inventory, sets each customer's credit limit, and views reports.
- **Customer**: everyone else. A customer signs up, browses products, adds them to a cart,
  pays by **cash** or **credit**, and then sees a bill and an order history.

The backend already exists and was tested in Postman. My job is the **frontend only**: mirror each
working Postman request with `$.ajax` and give it a colourful, responsive, accessible UI.

| A8 | **Customers + credit limit** | Paginated customer table (name, email, mobile, credit limit, credit used, available). The admin edits `creditLimit` with a PATCH using an updateMask. Validation: the new limit can't be negative and can't be below `creditUsed` (see Q3). | 4.3, 4.4 |
| A9 | **Dashboard** | Stat cards: total products (aggregation count), low-stock count, customers, total sales. | 3.12 |

**Reports** (date filters use a From / To date picker):

1. **Customer report**
   - All customers, all columns.
   - **Top 10 customers by total purchase amount**, From to To date.
   - **Cash purchase** report per customer, From to To date (uses the existing `paymentType + createdAt` index).
   - **Credit purchase** report per customer, From to To date.
2. **Inventory report**
   - Current stock: all, or category-wise (with a category filter and per-category totals).
   - **High stock (qty > 100)** and **Low stock (qty < 15)**.
3. **Sales report**, From to To date
   - (a) all sales, (b) category-wise, (c) cash-wise, (d) credit-wise.
   - **Top 10 selling items** and **Bottom 10 selling items** (by quantity sold).

How it works: Firestore REST has no "GROUP BY". I fetch the orders in the date range with
`runQuery`, then **group and total them in JavaScript** (by customer, category, product or
payment type). Simple CSS bar charts show the totals.

### 2.3 Cross-cutting rules (from the brief)
- All server calls go through **one** module, `js/api.js`. Pages only see plain JS objects, and the
  `toFirestore()` / `fromFirestore()` helpers do the typed-value conversion.
- No Firebase SDK, frameworks, CSS libraries, TypeScript, or build step. jQuery 3.x loads from the
  official CDN with a local fallback copy in `/vendor`.
- Route guards (admin pages for `ADMIN_EMAIL` only; customer pages need a login), double-submit
  protection, friendly error toasts, no inline CSS/JS, no `console.log`, and labels and alt text everywhere.
- Responsive from 320px to 1440px, AA contrast, keyboard friendly, `prefers-reduced-motion` respected.

## 3. What I found in /docs (worth knowing before coding)

1. **Category count:** `seed-shop.ps1` creates **12** categories × 5 products = 60. The brief lists
   **13** (it adds *Pet Supplies*), so Pet Supplies probably exists with **0 products**. That's fine:
   it will show the "empty state" design. Postman request **2.3** also creates a category called
   **"Books"**, so a stray "Books" category may also exist (see Q6).
2. **The folder is `Docs` (capital D)**, not `docs`. Windows doesn't care, but GitHub links and
   case-sensitive servers do. I suggest renaming it to `docs/` (see Q7).
3. **Order IDs** in Postman are `'ORD' + Date.now()`. I will use the same format so bills have readable IDs.
4. **`qty` comes back as a string** (`integerValue: "50"`). `fromFirestore()` converts it to a
   number, and `toFirestore()` sends whole numbers as `integerValue` strings and prices as
   `doubleValue`. Because JS has only one number type, the converter needs a hint for which fields
   are integers. I will keep a small list (`qty`) so `price: 1000` is still sent as a double.
5. **`runQuery` responses** are an array like `[{document: …}, …]`. When nothing matches, they
   return `[{readTime: …}]` with no `document`, and the code must handle that.
6. **`runQuery` has no `nextPageToken`**. Only the plain `GET` list has one. So:
   - Admin "All products" uses `GET` + `pageToken` (true token pagination, as in Postman 3.3/3.4).
   - Filtered lists (by category, active-only, search) use `runQuery` with `limit` + `offset`.
     This is easy to explain and fine for 60 products.
7. **Some new queries need composite indexes.** The store must filter `isActive == true` *and*
   sort by title (and sometimes also filter by `catId`). Firestore will answer with an error that
   contains a "create index" link. When that happens, I'll show you the link. Likely ones:
   - `inventory (isActive ASC, title ASC)`
   - `inventory (isActive ASC, catId ASC, title ASC)`
   - Order history: I'll **sort by date in JavaScript** to avoid needing a `(customerId, createdAt)` index.
8. **Race conditions at checkout.** `increment(-n)` doesn't stop stock going below 0 if two people
   buy the last item at the same moment. Fix: in the commit, attach a
   `currentDocument.updateTime` precondition (the time I read each product). If anything changed
   since I read it, Firestore rejects the **whole** commit, and I show "Stock changed, please
   review your cart". It's one extra line per write and a good concept to explain (see Q9).
9. **Firestore test mode expires about 20 Dec 2026** (about 4 weeks from today, 21 Nov 2026).
   Phase 7 (security rules) must be done before then, or every request will start failing.

## 3b. Phase 0 revision (21 Nov 2026): real photos and a warm theme

- **New field `inventory.imageUrl`** (string, optional). It is a path such as
  `assets/images/products/wireless-earbuds-pro.jpg`, or a full `https://` URL.
  The 60 existing products were filled in by `docs/add-product-images.ps1`, which PATCHes with updateMask `imageUrl` only.

  `assets/images/`. Each one was checked by eye. Credits: `docs/IMAGE-CREDITS.md`.
- **Theme:** warm and light. Ivory and peach backgrounds, terracotta brand colour, sage and mustard accents,
  cocoa text, Fraunces serif headings.
- **Store layout:** announcement bar, header with a large search box, account/orders/cart actions, a live category bar,
  a bento hero with photos, photo category circles, "Trending now" product cards, and a credit banner.

**Phase 4 decision (store paging):** the store loads all active products in one request and filters, searches,
sorts and pages them in JavaScript. This allows "contains" search and sorting by price without any new
Firestore index. The admin pages still use server-side `pageToken` and offset paging.
